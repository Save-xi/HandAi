## 1. H2O 数据实际是什么

当前使用仓库根目录下 `datasets/H2O/raw`，以及 `datasets/H2O/processed/cross_subject_v2_open_release`。原始记录来自 cam4，NPZ 保留 `landmarks_3d`、`landmarks_2d` 和 `controls_9ch`。

| 项目 | M0 确定的定义 | 依据 |
|---|---|---|
| 原始布局 | 128 个数；右手标注位在索引 64，右手 21×3 坐标在 65–127 | [官方数据说明](https://github.com/taeinkwon/h2odataset#hand_pose)与本机全部原始帧 |
| 3D 坐标 | 相机坐标，单位 **米**；当前只用右手 | [作者关于单位的回复](https://github.com/taeinkwon/h2odataset/issues/13#issuecomment-1241233736) |
| 点序 | OpenPose 21 点，原样保存，无重排 | [作者关于点序的回复](https://github.com/taeinkwon/h2odataset/issues/22#issuecomment-1735268412)及官方可视化连线 |
| 轴向 | 按官方投影推得：X 向相机图像右，Y 向下，Z 向前 | [h2oplayer.py](https://github.com/taeinkwon/h2oplayer/blob/main/h2oplayer.py) 的 `hand_proj` 使用相机内参、零旋转平移直接投影；这是代码依据的推断 |
| 采样时间 | 官方录制 30fps；本机 `timestamps_s=frame_id/30` | [论文 §4.1](https://arxiv.org/html/2104.11181v2#S4.SS1)及预处理源码、全部 NPZ 数值核对 |
| 标注含义 | 整只右手有无标注；不是逐关节可见性或检测置信度 | 原始格式只有整手有效位，本机无逐点可见性字段 |

具体索引：0 腕点；1–4 拇指 CMC/MCP/IP/指尖；5–8 食指 MCP/PIP/DIP/指尖；9–12 中指；13–16 无名指；17–20 小指。完整字段名见配置。OpenPose 与 MediaPipe 在此采用相同索引拓扑，并不表示二者的坐标空间或关键点定位结果可互换。

184 个 take 本机均未发现 `cam_intrinsics.txt` 或 RGB 目录。已保存的 `landmarks_2d` 全部等于“原始相机 XY 减腕点，再除以二维掌长”的旧公式，最大数值差为 0；它不是图像坐标或针孔投影。当前 `controls_9ch` 是这套替代坐标经规则映射产生的代理标签，不能作为实体手关节真值，也不能直接作为新 M2 的统一目标。

论文说明标注经过 MANO 拟合及时间平滑/插值。本机测得同一人的掌长也近乎恒定。因此原生标注预测是较理想的数据域；输入虽然只取过去标注，但标注生成过程本身不等同于在线因果检测器，不能据此声称真实摄像头抗噪声或延迟补偿能力。[标注方法 §3.3](https://arxiv.org/html/2104.11181v2#S3.SS3)

|---|---|---:|
| subject1/o1/5/cam4 | 321–349 | 29 |
| subject2/h1/3/cam4 | 860–891 | 32 |
| subject3/k2/3/cam4 | 482–494 | 13 |

全部其余连续有效原始帧都已保留，没有发现映射筛选造成的额外有效帧排除。这里是按原始有效位和连续段进行的独立清点，没有重跑旧映射器。933 帧只可称为无标注，不能当作检测器漏检或全部遮挡帧。

全量检查未发现非有限坐标、重复源帧、人员跨切分、帧号断续或元数据不一致。原始点转换为 float32 后与 NPZ 的最大绝对差为 0；所有存储时间与帧号/30 的最大差为 0。保留帧的 Z 均为正。以上证明数据转换及当前存储内容一致，不证明标注本身没有误差。

## 3. 后续关键点实验定义

首轮任务为 `h2o_camera3d_right21`：过去 30 帧相机 3D 预测未来 21 点，采用一个锚点的腕点与尺度处理整个窗口：

`q_j(τ) = (p_j(τ) - p_0(t)) / s(t)`

`s(t)` 首选 `||p_9(t)-p_0(t)||`，低于下限或不有限时用 `||p_5(t)-p_17(t)||` 回退，两者都不可用则该锚点无效。未来标签和反变换均使用同一锚点参数，保留未来腕部平移；不旋转对齐、不用未来尺度、不做 `[0,1]` 截断。

训练集保留帧的正掌长中位数为 `0.09531036054196106 m`。尺度下限取其 1%，即 **`s_min=0.0009531036054196106 m`**。该统计仅使用 subject1+2；验证/历史复评只做检查，不参与拟合。当前三个切分均有 0 个掌宽回退帧、0 个尺度无效帧。此下限只是防退化参数，不是关键点质量置信度。

历史网格为 30Hz、30 个观测（首尾跨度 29/30 秒），首轮锚点步长 1。输出未来第 1–5 步，分别在 50/100/150ms 评价；50ms 使用第 1、2 步插值，100ms 对应第 3 步，150ms 使用第 4、5 步插值。显式无效帧、会话边界或断段都不能跨越；一般数据的目标包围间隔不得超过 `2/30 s`。历史插值只能使用预测锚点时已经可用的观测。

H2O 时间是名义媒体时间，不能测量实际采集抖动。摄像头任务另用其 PTS/记录的采集与就绪时间，禁止与 Unix 时间直接相减。输入有效性和目标有效性分开记录；这里没有逐关节遮挡标签，也不使用左右手分类分数伪造逐点置信度。

现有连续有限标注中，潜在锚点数量如下。它们是数据清点结果，**尚未生成 M1 训练窗口**；每帧并非独立统计样本。

| 切分 | 历史够 30 帧 | 有 50ms 标签 | 有 100ms 标签 | 有 150ms 标签及完整 5 步路径 |
|---|---:|---:|---:|---:|
| train | 51,198 | 50,988 | 50,883 | 50,673 |
| val | 26,891 | 26,771 | 26,711 | 26,591 |
| 历史复评 | 28,940 | 28,836 | 28,784 | 28,680 |

共有 6,293 个保留帧位于片段预热区，另有 1,085 个历史充足锚点缺少完整未来路径。三个已舍弃短段都不足以形成“30 帧历史＋5 步未来”的完整样本；32 帧段本可提供 1 个仅 50ms 的锚点。首轮采用现有 217 段，明确保留这一排除，不把全部原始帧当作训练覆盖率的分母后隐去排除。

主指标为锚点掌长归一化的 3D MPJPE，辅报反归一化后的毫米 MPJPE、腕部位移误差、相对指形误差和逐锚点误差 P95。按时距分别列出，主汇总对序列等权，并另报按帧汇总与覆盖率；50/100ms 用于主要研发比较。模型选择只用 validation。M2 的通道参考将统一采用“姿态插值→同一手势状态→同一映射”，与旧 9 通道标签报告分开。

具体地，每个锚点/时距的归一化 MPJPE 是 21 个点的欧氏误差均值，乘 `1000*s(t)` 得到该锚点的毫米 MPJPE。腕部误差只比较点 0；相对指形误差对预测和目标分别减去各自的未来腕点，再对其余 20 点求欧氏误差均值。这个辅助误差的去平移操作不改变模型使用的锚点归一化，也不向模型提供未来腕点。

## 4. 可以复用的姿态证据

FreiHAND 历史检测发生于 **2026-08-24**，共 3,960 张静态图；2026-09-15 已用旧预测和 GT 重算，本轮只整理并比较两份指标数值。原配置为 `static_image_mode=true`、`prefer_any_hand=true`、最多检测 2 只手，历史环境为 PC、MediaPipe 0.10.14。不能把旧报告标题中的 single-right-hand 范围当作实际任意手选择配置。

| 指标 | 历史值 |
|---|---:|
| 全 GT PCK@5/10/20/30px | 38.012% / 67.631% / **84.097%** / 87.557% |
| 有效预测 PCK@20px | 92.713% |
| 21 点完整率 | 90.707%（3,592 张有效，368 张无效） |
| 有效预测 2D MPJPE | 8.713px |
| 记录的检测加手选择 P50 / P95 / 最大耗时 | 19.891 / 23.338 / 39.865ms |
| 记录中超过 50ms | 0 / 3,960 |

84.097% 和 92.713% 的分母不同，不能互换。“完整率超过 90%”也不等于“姿态准确率达到 90%”。本轮没有重新运行检测器；这些耗时不是当前环境、连续右手或 HoloLens2 的新测速。正式姿态比较暂采用全 GT PCK@20px，并辅报其他阈值、有效点误差和完整率；图像缩放/裁剪后须还原原评测坐标。

## 5. 摄像头与外部条件缺口

本机 `D:\HandAiVideos\camera_domain_dev_v1` 有 V1–V7 共 4,601 帧，按容器元数据约 153.587 秒，均为 1920×1080；名义 FPS 约 29.914–30.019，并非都精确为 30。另有 `v1_pilot` 和 `mirror_check`。本轮仅读取容器信息，没有全量解码、重跑检测或验证全部 PTS。V1–V7 保持开发用途，不能由文件数推断人数或独立会话数。

| 缺口 | 对后续阶段的影响 | 下一步责任 |
|---|---|---|
| 项目书“姿态准确率 90%”没有确定阈值、分母、数据集和设备 | 无法宣布正式达标；不阻塞 M1 原生预测 | 负责人确定验收口径，AI 提供研发指标 |
| HoloLens2 是否可用、OS、SDK/Unity 和推理后端尚未提供 | M5 兼容性、端侧测速和量化路径不能定案 | 协作方提供设备条件，AI 再做导出验证 |
| H2O 本机无对应 RGB/内参 | 可做原生 3D；不能作为已对齐摄像头输入 | 需要时补合法取得的原始资产或单独建摄像头任务 |
| 新参与者/会话、独立姿态及手势转换标签缺失 | M3 独立泛化和真实手势提前/误触发结论未完成 | 按路线图采集/标注；M1/M2 可先用 H2O |
| H2O 无逐点遮挡真值，标注已拟合和平滑 | 不能从原始有效位推断遮挡鲁棒性 | M3 使用真实检测缺失与独立标注分层 |
| 真实系统 ≤100ms 的跨模块时间定义未定 | 本机 AI 耗时不等于全系统验收 | 协作方与负责人定义链路，AI 预留时间与有效性字段 |

以上未知项已记录；不把它们当作本机 M0 无法完成的理由。后续工作仍限 AI，设备驱动、通信和 Unity 实现由协作方负责。
