# AI 路线图：先修摄像头基础，再验证预测收益

更新：2026-09-21，依据负责人提供的 `HandAi_AI_Review_20260921.md` 重排。已核对 PR #20 合并后的相关源码、当前接口和 CI 配置；报告中的复现实测仍归属于该次审核，本次没有重做完整审计或训练。

**当前状态：M0/M1/M2 的 H2O 工作已完成；下一步先实施 M3-A。M3-A/B/C、M4、M5 均为待实施计划。** 本次交付是路线与验收范围的调整，报告末尾给实现 agent 的任务描述作为后续工作依据。

AI 侧负责姿态、几何特征、手势、预测、训练评测与可调用输出。Unity、5G、RS485、SVH/AUBO、机械臂和设备驱动由协作方负责；只核对数据、时间、模型后端与消费接口。

## 3. M3-A：先稳定几何、坏帧与映射边界

### 3.2 坐标契约与输入行为

保留原始图像归一化 XY 用于绘制和边界检查，另外提供几何点。官方定义中 x/y 分别按图像宽/高归一化，z 以腕部为原点，量级约与 x 相同；不能将原始三个轴直接称为已统一尺度的相机三维。[MediaPipe Hands 输出定义](https://chuoling.github.io/mediapipe/solutions/hands.html#output)

首个待验证方案为图像宽度单位的 `g=(x, y*H/W, z)`，即先消除 XY 的像素比例差，再检查相对深度的适用性。这是基于上述定义的工程方案，不是公制 3D 重建。明确 x 向右、y 向下以及 z 的相对方向；不得把 H2O 的米尺度下限搬来使用。可另作 world landmarks 对照，但其原点/坐标与 H2O 不同，也不作为已知真值。

摄像头任务暂命名为 `camera_mediapipe_geometry_xyz_v1`，保存图像宽高、原始点、几何点和转换说明；这是**拟议任务定义，尚无实现**。旧计划中的 `camera_mediapipe_image_xyz` 仅代表未经此次整改的原始表示，两者不能只凭 63 维互换。缺少尺寸/坐标声明的外部输入需明确报无效或给出可解释的适配错误，不能猜测宽高比。

处理顺序为：点数/维数/有限值 → 几何转换 → 有效掌尺度与必要骨段 → 图像边界 → 特征与手势。掌长退化时可按明确规则尝试掌宽，二者均无效则拒绝；骨段规则需避免把正常屈曲、二维重叠误当作三维退化。

流式运行对缺点、缺 XYZ、NaN/Inf、重合点等输出标准不可用状态和原因，避免在 JSON 中传播非有限值。失效帧当帧不可消费，并按明确规则重置手势、释放状态和预测历史；恢复后的预热须计数。有效但无法分类的 `unknown` 独立处理，不能因延长旧手势而掩盖丢手。

### 3.3 释放候选、语义版本与验证

只先做一个最小连续过渡候选，参数写入配置。对相同有效姿态序列报告每通道单帧变化的 P95/最大值、转换时刻和新增滞后；同时检查 open↔unknown、open↔pinch、正常张开、丢手和恢复。阈值变化用开发数据检查，修复宽高比后不得默认旧手势阈值仍合适。

如果新增释放权重等状态，未来预测和参考均须复制**完整状态**：手势候选、确认计数、释放权重及必要时间。按规则采样点推进，分数时刻查询不能额外更新去抖或平滑状态。所有更新只依赖当时已知的信息。

几何或映射语义变化时更新可读版本与参数，重建相应共同参考。旧配置不能静默进入新计算；历史报告原样保留，旧重放显式选择旧语义或清楚说明不兼容。新旧映射的 RMSE 目标不同，应分表；比较映射本身时使用同一姿态的跳变、滞后及人工标注，而非直接比较两套代理标签的 RMSE。

**M3-A 完成条件：**

- 固定合成几何覆盖方形、16:9、9:16 图像编码、平面旋转和等比例尺寸；在预设数值容差内，归一化距离比例及角度符合预期，显示位置仍正确。该测试不宣称检测器本身具有旋转不变性。
- 覆盖 0/5/20/21 点、缺失 XYZ、非有限坐标、零掌长/掌宽、必要骨段退化，以及“有效→坏帧→有效”；坏帧不能产生 `control_ready=True`，且不打断后续处理。
- 复现审核报告的 curl `0.4499→0.4501` 例子。**建议研发门槛**：最大通道跳变由约 0.470343 降到不超过 0.05；有效转换相对旧实现增加的滞后不超过一个源采样周期，同时报告实际毫秒。它们是本阶段待评估的取舍，不是设备验收指标；失败时保留旧/新对照与原因，不宣称整改完成。
- 输入失效的不可用状态立即生效，不受上述连续释放时间约束。没有有效当前观测时不把残留输出记为恢复。
- CPU 预测 job 确认能导入 PyTorch；M1/M2 的指定可重建用例真实执行，不能因缺 torch 全部跳过仍称覆盖完成。外部 ignored 权重的历史用例另列依赖，不要求下载 H2O 或发布大权重。

交付配置、边界测试、少量前后转换样例及一次修复后开发视频检查。此阶段不需要重跑全部 H2O 三种子训练。

## 4. M3-B：摄像头域简单预测与完整计时

### 4.1 数据和三个对照

复用 [camera_domain_eval.py](../experiments/intent_prediction/intent_prediction/camera_domain_eval.py) 的媒体 PTS 与名义 FPS 回退，以及 [HandPipeline](../src/pipeline.py)。先核对 V1–V7 的人员/会话来源；会话先切分再建窗。若来源无法恢复，只能标为历史开发片段，不能把视频文件数当作独立人员/会话数。

每帧保存来源视频、人员/会话（未知时明记未知）、帧号、PTS/时间来源、宽高、原始点、几何点、有效性/失效原因和段号。输入只用锚点及之前已到达的观测；缺帧与重启断段，不跨无效区间补出标签。历史归一化只使用当前锚点腕点/尺度，摄像头尺度统计和阈值只在开发训练部分确定。

三种方法来自同一输入、锚点、映射版本和参考：保持当前通道、保持姿态后推进状态并映射、常速度姿态后推进状态并映射。速度拟合窗口在验证集选择；先固定简单赢家，再做后续复评。H2O checkpoint 不直接接到新摄像头坐标。

复用 M2 的因果查询规则：中间姿态沿规则时间网格推进完整状态，50/100/150ms 先插值姿态再映射。缺参考时如实记录不可评分；预测失败不能从已有参考的评分分母消失。输入与参考同来自 MediaPipe 时，名称为“检测轨迹代理评测”。

### 4.2 时间起点和实验输出

当前 [main.py](../src/main.py) 默认在检测结束后生成 payload timestamp，视频循环也未显式传媒体时间；这个值不能直接拿来当 M3 的源锚点。视频使用 PTS，回退时记录 FPS 和回退次数；实时本机使用明确的单调时钟，如果起点只能取 `source.read` 返回，写明该范围，不称为曝光时间。

保留纯算法和计入运行成本两套结果。分别记录检测完成、预测入队、开始/结束及特征/手势/映射全部完成的时间。离线回放须将处理耗时、排队和丢弃转换到声明的媒体调度时间；仅测单帧 forward 再加到 PTS，不能证明实时排队表现。

拟议的独立候选输出至少包含：

| 字段组 | 内容 |
|---|---|
| 来源 | `frame_id`、`source_time`、`timebase`、`timestamp_source` |
| 时间 | `horizon_ms`、`target_time`、`ready_time`、各阶段耗时 |
| 语义 | `task_id`、几何/映射版本、通道顺序 |
| 结果 | 当前基础值、候选预测值、`valid`、`on_time`、回退/失效原因 |

这些是待实现的实验字段，当前运行接口见 [AI 对接入口](ai_interfaces.md)。基础输出与候选分开记录；下游设备成员只需消费约定字段。

同一时间轴上 `target_time=source_time+h`，且 `ready_time<=target_time` 才算按时；ready 包含检测、排队、预测及后处理。逾期计 deadline miss，当前观测有效时按预先规定的简单方式回退；输入无效或没有可用当前目标时单列无输出。报告剩余前视时间，不能把 150ms 输出冒充更远预测。软件扰动实验使用同一源帧、到达安排和丢包事件，方法自己的计算与队列成本分别计入；无需实现通信模块。

**M3-B 完成条件**：可重复运行的开发序列/CLI、带时间的输出样例，以及 50/100/150ms 的逐序列误差、P95、失败、无输出、总输出/预测覆盖率、按时率、转换跳变与滞后。误差使用可评分参考分母；覆盖率以源流全部应评时刻为分母，包含预热、坏帧、丢弃和逾期。少数开发会话只能支持工程和代理结论。

## 5. M3-C：补真实证据，再决定是否训练模型

建议首轮新增 3 人 × 2 会话 × 5 类片段，每段 20–30 秒，约 10–15 分钟；覆盖静态/旋转、快速屈伸、捏合转换、侧视、遮挡/出框/恢复。先固定开发与留出用途；新参与者用于独立评估，不参与阈值调整。只有同人新会话时，结论限定同人跨会话。

关键点可先每段抽 5 帧，约 150 帧，标注图像坐标与可见性；手势另外连续标注 open/fist/pinch/unknown 及事件区间，不能用稀疏关键点标注代替转换时间标签。仅有 RGB 二维标签时报告二维误差，不制造公制 3D 真值。

交付全 GT 姿态指标（漏检进入规定分母）、完整率、逐类 precision/recall/F1、混淆矩阵、转换提前/滞后、误触发，以及 M3-B 的按时/回退结果。PCK 的像素阈值对应原图或明确还原后的坐标；几何归一化误差、像素误差和通道 RMSE 分开报告。按人/会话配对统计，独立组不足时只报告有限范围结果。

按失败归因作下一步决定：

| 主要证据 | 下一步 |
|---|---|
| 几何或规则边界仍主导误差 | 回到 M3-A，不用预测网络掩盖基础问题 |
| 人工标注显示检测误差/漏检占主导 | 提前 M4 感知对照 |
| 检测/参考足够可靠，简单外推在转向、加速上反复失败 | 用开发侧失败片段训练一个同域小模型，复用 M1/M2 框架 |
| 简单方法已够用，神经候选无稳定收益 | 保留简单方法，停止该轮模型扩展 |

训练和调参只使用开发数据；如果已查看的留出会话被用于改模型或选阈值，将其改记为开发/历史复评，并另留新数据做独立评估，不能继续称为未见测试。

神经模型再启动时仍需三个种子、validation 选型和相同参考。研发继续条件建议沿用：50/100ms 均值改善至少 5%、两个时距分别不退化、对应 P95 退化不超过 2%、多数会话/种子改善，并在计入计算成本及回退后成立。基线接近零时改报绝对差；不能通过删掉难帧换取覆盖率或误差优势。这不是项目书验收。

## 6. M4：由感知证据触发的模型对照

采用一个现成 MMPose 手部候选与 MediaPipe 同口径比较，记录具体权重、输入尺寸、手框来源和运行设备。系统比较计入检测框、裁剪、关键点、手选择与后处理；真值手框只能作为上限分析。二维候选仅用于二维评测，不伪造 Z 接入三维特征。

FreiHAND 复用静态证据，InterHand2.6M 先取有代表性的右手/交互遮挡子集；本机新标签可先提供开发证据。报告全 GT PCK/MPJPE、完整率、漏检、P50/P95/最大耗时和超过 50ms 比例，区分静态任意手与连续右手。调整项目书中的 Cascade R-CNN/ResNet-101 路线需给出选型依据；只有现成候选仍不能满足明确需求时，再评估自训练检测网络。

## 7. M5：有效候选与后端明确后再导出

协作方提供 HoloLens2 的实际系统、SDK、可用后端和消费约定。AI 侧先验证小样本算子/维数/后端兼容，再考虑 ONNX FP32 及适用量化；不预设某个 Unity 推理后端，也不承接设备、驱动或通信实现。

验收为权重、可读配置、输入输出样例、导出前后数值一致性、精度/大小/内存和 batch=1 延迟对照。量化统计仅来自开发训练/验证数据。无设备时交付 PC 可行性并保留端侧缺口；姿态模型、预测头、组合流程分别标明范围，不能把一个模型导出称为全系统部署。
